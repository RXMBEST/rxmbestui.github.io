#1. What is RXM UI?

RXM UI is a UI-only library for Roblox scripts. It gives you a polished interface and a loading screen. It does not contain any game features. You write the features (your "engine"), and the library shows them as toggles, sliders, buttons and so on.

The design is inspired by the iPhone Dynamic Island:

  1. Pill: a small capsule at the top of the screen. This is the UI when it is closed.
  2. Notification: when something happens, the pill stretches into a small banner, then shrinks back.
  3. Panel: tap the pill and it expands into the full window with tabs.

Everything is animated with springs, glow, neon borders and other effects. Colors, intro, icons and fonts can all be customised.

The mental model

Library -> Window -> Tabs -> Elements -> your Callback (your logic)
  • Library: the thing you load. It holds themes, intros, icons and fonts.
  • Window: one UI (pill + panel). You can create more than one.
  • Tab: a page inside the window.
  • Element: a control on a tab (Toggle, Slider, Button...).
  • Callback: a function you provide. It runs when the user changes the element.

#2. Quick start

Step 1: Get the loadstring

The official copy is hosted on GitHub. Use this loadstring:

loadstring(game:HttpGet("https://raw.githubusercontent.com/RXMBEST/RXM-UI/refs/heads/main/RXM_UI_Library.lua"))()

You can also upload your own copy of RXM_UI_Library.lua to GitHub (or a Gist or Pastebin) and put its raw link inside the loadstring instead.

Step 2: Write your script

local Library = loadstring(game:HttpGet("https://raw.githubusercontent.com/RXMBEST/RXM-UI/refs/heads/main/RXM_UI_Library.lua"))()

local Window = Library:CreateWindow({ Name = "My Hub" })
local Main   = Window:AddTab("Main")

Main:Section("Features")

Main:Toggle({
    Name = "Auto Farm",
    Default = false,
    Callback = function(on)
        print("Auto Farm is", on)
    end,
})

Main:Slider({
    Name = "Speed", Min = 0, Max = 100, Default = 25, Suffix = "%",
    Callback = function(value) print(value) end,
})

Main:Button({
    Name = "Say hello",
    Callback = function()
        Window:Notify({ Title = "Hello", Content = "It works!", Type = "success" })
    end,
})

Window:CreateSettingsTab()   -- optional built-in Settings tab

Step 3: Use it in game

  • Wait for the loading screen to finish. A small pill appears at the top of the screen.
  • Tap or click the pill to open the panel.
  • Drag the header to move the panel.
  • Tap anywhere outside the panel to close it back to the pill.
  • To remove the UI completely, call Window:Destroy(), or show the Destroy UI button in Settings with DestroyUI = false and press it (tap twice to confirm).
  • RightControl hides or shows the whole UI (change it with ToggleKey).

#4. Elements

Every element is created from a tab: Tab:Element({ ... }). All of them accept Name, Icon and Callback. Most return an object with Get() and Set(value, silent). Pass silent = true to change a value without running the callback.

If you add Flag = "name", the latest value is also stored in Library.Flags.name.

Section, Label and Paragraph

Main:Section("Combat")              -- small heading
Main:Section("Combat", "sword")     -- heading with an icon
Main:Label("Some information")      -- muted text line (returns :Set(text))
Main:Paragraph({ Title = "About", Content = "Long text that wraps automatically." })

Button

Main:Button({
    Name = "Teleport",
    Icon = "map-pin",
    Solid = true,                    -- optional: filled with the accent color
    Callback = function() print("clicked") end,
})

Toggle

local t = Main:Toggle({ Name = "ESP", Default = false, Callback = function(on) print(on) end })
t:Set(true)      -- turn on (runs the callback)
t:Get()          -- true or false
t:Toggle()       -- flip it

Slider

Main:Slider({
    Name = "Walk Speed",
    Min = 16, Max = 200, Default = 16,
    Step = 1,              -- rounding step (decimals allowed, e.g. 0.5)
    Suffix = " studs",     -- text after the number
    Callback = function(value) print(value) end,
})

Users can drag the bar or tap the number box and type a value.

Dropdown

local d = Main:Dropdown({
    Name = "Mode", Options = { "Easy", "Normal", "Hard" }, Default = "Normal",
    Callback = function(choice) print(choice) end,
})

Main:Dropdown({                      -- multi select
    Name = "Targets", Options = { "A", "B", "C" }, Multi = true, Default = { "A" },
    Callback = function(list) print(table.concat(list, ", ")) end,
})

d:Refresh({ "New 1", "New 2" })     -- replace the options later

Input

Main:Input({
    Name = "Player name", Placeholder = "type here",
    Numeric = false,       -- true = digits only
    Live = false,          -- true = callback on every keystroke
    Callback = function(text) print(text) end,
})

Keybind

Main:Keybind({
    Name = "Fly key", Default = Enum.KeyCode.F,
    Callback = function() print("key pressed") end,   -- runs when the key is pressed
    Changed  = function(newKey) print(newKey) end,    -- runs when the user rebinds
})

The user taps the key box and presses a new key. Esc cancels and Backspace clears the bind.

ColorPicker

Main:ColorPicker({
    Name = "ESP color", Default = Color3.fromRGB(255, 80, 80),
    Callback = function(color) print(color) end,
})

Foldout

A collapsible group. Build its content inside Build:

Main:Foldout({
    Name = "Advanced", Open = false,
    Build = function(tab)
        tab:Toggle({ Name = "Option 1" })
        tab:Slider({ Name = "Option 2", Min = 1, Max = 10, Default = 5 })
    end,
})

IconPicker and FontPicker

Cards that open a searchable list so the user can pick an icon or a font:

Main:IconPicker({ Name = "Pick icon", Callback = function(iconName) print(iconName) end })
Main:FontPicker({ Name = "Pick font", Callback = function(fontName) Library:SetFont(fontName) end })

#5. Notifications

Window:Notify({
    Title = "Saved",
    Content = "Your settings were saved.",
    Type = "success",     -- "info" (default), "success", "warn" or "error"
    Duration = 3.5,       -- seconds
    Icon = "star",        -- optional custom icon
})
  • When the UI is closed, the notification appears inside the pill (Dynamic Island style).
  • When the panel is open, it appears as a toast in the corner. Tap a toast to dismiss it.
  • Library:Notify({...}) sends the notification to the most recent window.
  • If one of your callbacks throws an error, the library shows it as a red notification instead of crashing the UI.

#6. Loading screen (intro)

The on/off switch

local LOADING_SCREEN = true      -- true = show the intro, false = skip it

local Window = Library:CreateWindow({ Name = "My Hub", Intro = LOADING_SCREEN })

You can also use Library:SetIntroEnabled(false) before CreateWindow. If Intro is set in CreateWindow, it wins over the global switch. Users can skip a running intro by tapping or clicking the screen (there is no on-screen text for it). Set Skippable = false in the intro to disable skipping.

Creating your own intro

Library:AddIntro("MyIntro", {
    Style    = "Emblem",                       -- Emblem, Minimal, Cinematic or your own style
    Text     = "MY HUB",
    Subtitle = "WELCOME BACK",
    Image    = "rbxassetid://17297011003",     -- id, rbxassetid, https link, or a file in your workspace
    Sound    = "rbxassetid://86045706626808",
    Duration = 5,
    Colors   = { Primary = Color3.fromRGB(255, 60, 80), Secondary = Color3.fromRGB(120, 0, 20) },
})
Library:SetIntro("MyIntro")                    -- make it the active intro

Text, Subtitle RXM HUB, WELCOME Title (typed out letter by letter) and small text under it.
Image none Picture in the center. Works with decal ids too.
Icon none An icon (for example "crown") instead of the image or first letter.
Letter first letter of Text Letter shown when there is no image or icon.

Sound, Volume none, 1.5 Sound played during the intro.

Built-in styles

  • Emblem: fog, light beam, particles, rotating rings, glitch title and progress bar.
  • Minimal: clean logo ring, typed title, thin progress bar.
  • Cinematic: letterbox bars, zooming title with a light sweep, floating dust.
  • YinYang: a big spinning yin-yang with a rotating tick ring, orbiting light and dark orbs, swirling particles, black and white ripples, a typed title and a progress bar.

Quick setters

Library:SetIntroText("MY HUB", "WELCOME")
Library:SetIntroImage("rbxassetid://123456")
Library:SetIntroSound("rbxassetid://987654", 2)
Library:SetIntroStyle("Cinematic")
Library:SetIntroDuration(4)
Library:SetIntroColor(Color3.fromRGB(80, 170, 255))   -- Library:SetIntroColor(nil) = follow UI color again
Library:PlayIntro()                                    -- play it right now (preview)

Writing a completely custom style

Library:AddIntroStyle("Flash", function(ctx)
    local label = ctx.Make("TextLabel", {
        Size = UDim2.fromScale(1, 1), BackgroundTransparency = 1,
        Text = ctx.Config.Text, TextScaled = true, Font = Enum.Font.GothamBold,
        TextColor3 = ctx.Colors.Primary,
    }, ctx.Stage)

    return {
        -- t = seconds elapsed, dt = frame time, u = progress 0..1, p = smoothed progress
        Step = function(t, dt, u, p)
            label.TextTransparency = 1 - p
        end,
        OnComplete = function() end,   -- optional: runs when progress reaches 100%
    }
end)

Library:AddIntro("FlashIntro", { Style = "Flash", Text = "HELLO", Duration = 3 })

The ctx table contains: Stage (the full-screen canvas), Config, Colors, Viewport, Compact (true on phones), Make(class, props, parent), Tween(...), OnImage(fn), StatusAt(progress) and Icon(parent, size, color).

#7. Key system

The key system asks the player for a key before your hub opens. A small panel appears in the same colors and font as the rest of the UI. A correct key lets the script continue. If the player closes the panel, CreateWindow returns nil and nothing else loads.

It works like the key system in Rayfield: turn it on with KeySystem = true (or off with false) and put the rest in KeySettings.

The order is always: key panel, then the loading screen, then the window.

Quick start

local Window = Library:CreateWindow({
    Name = "My Hub",
    KeySystem = true,                       -- true = ask for a key, false = no key panel
    KeySettings = {
        Title = "My Hub",
        Subtitle = "Key System",
        Note = "Join our Discord to get the key",
        FileName = "MyHubKey",              -- file that remembers the key
        SaveKey = true,                     -- true = remember the key, false = ask every time
        GrabKeyFromSite = false,            -- true = Key[1] is a link to a key list
        Key = { "RXM-1234-ABCD", "RXM-VIP-9999" },   -- accepted keys
        KeyLink = "https://example.com/get-key",     -- adds a Get Key button
        Discord = "https://discord.gg/yourinvite",   -- adds a Discord button
    },
})
if not Window then return end    -- the player closed the key panel

-- everything below only runs after a valid key
local Tab = Window:AddTab("Main", "home")

Set KeySystem = false and the key panel is skipped, so your hub opens right away. KeyLink and Discord are RXM extras: they copy the link when tapped, and both buttons are optional.

Good to know: KeySettings is only used when KeySystem = true. If you write KeySettings but forget KeySystem, no key panel is shown.

The true / false switches

Every on/off choice is a plain true or false.

Setting true false
KeySystem Ask for a key before the hub opens. No key panel, the hub opens at once.
SaveKey Remember the key in a file, so the player does not type it next time. Never save. The player types the key every time.
GrabKeyFromSite The first item in Key is a link. The keys are downloaded from it. Key is a list of keys written in the script.
["KEY"] = true / false The key works. The key is disabled (shows This key has been disabled).
AutoLogin Skip the panel when the saved key is still valid. Always show the panel.
CaseSensitive ABC and abc are different keys. ABC and abc are the same key.

Old style (still works)

Scripts that were written before this update keep working. Key = { ... } takes the same options as KeySettings, and Key = true or Key = false acts like KeySystem = true or false.

local Window = Library:CreateWindow({
    Name = "My Hub",
    Key = {
        Keys    = { "RXM-1234-ABCD", "RXM-VIP-9999" },
        KeyLink = "https://example.com/get-key",
    },
})
if not Window then return end

Using it on its own

You do not need a window to use the key panel. Library:KeySystem waits until the player enters a valid key or closes the panel, then returns two values. It takes the same options as KeySettings.

local ok, info = Library:KeySystem({
    Title = "My Hub",
    Keys  = { "RXM-1234-ABCD" },
})
if not ok then return end          -- closed without a valid key
print("Welcome!", info.Key)

Set it once

If you want to keep the key settings in one place, store them with Library:SetKeyConfig and then pass KeySystem = true to CreateWindow. Anything you write in KeySettings still wins.

Library:SetKeyConfig({
    Key     = { "RXM-1234-ABCD" },
    KeyLink = "https://example.com/get-key",
})

local Window = Library:CreateWindow({ Name = "My Hub", KeySystem = true })

Key entries

A key can be a plain string, or a table when you want extra rules:

Keys = {
    "FREE-KEY-1",                                                    -- never expires
    { Key = "WEEK-2222", Expire = os.time({ year = 2027, month = 1, day = 1 }) },
    { Key = "VIP-3333",  Tier = "VIP", Note = "Thanks for supporting!" },
    { Key = "DEVICE-4444", HWID = "paste-the-device-id-here" },
}
  • Expire: Unix time in seconds (UTC). After that moment the key is rejected with This key has expired. os.time({ year = 2027, month = 1, day = 1 }) gives you the number.
  • HWID: locks the key to one device. Run print(Library:GetHWID()) on that device to get the id.
  • Tier and Note: anything you want. They come back to you in info so you can unlock VIP features.
  • You can also write keys as a dictionary: Keys = { ["FREE-KEY-1"] = true, ["VIP-2222"] = { Tier = "VIP" } }.

Turning it on and off (true / false)

The key system is a simple switch. true shows the key panel, false skips it and your hub opens right away.

-- 1) per window, like Rayfield
local Window = Library:CreateWindow({
    Name = "My Hub",
    KeySystem = false,      -- true = ask for a key, false = no key panel
    KeySettings = { Key = { "RXM-1234" } },
})

-- 2) one switch for the whole library
Library:SetKeyEnabled(false)    -- off: everything opens without a key
Library:SetKeyEnabled(true)     -- on again

-- 3) inside the key options (same as KeySystem = false)
KeySettings = { Enabled = false, Key = { "RXM-1234" } }

-- old style: Key = true or Key = false works the same way

KeySystem in CreateWindow and Library:SetKeyEnabled are the same switch, the last one you set wins. KeySystem = true without KeySettings uses the options you stored with Library:SetKeyConfig. While the key system is off, Library:IsKeyValid() returns true so your features stay unlocked.

Disabled keys (true / false)

In a key list, true means the key works and false means it was turned off. A disabled key shows This key has been disabled instead of Invalid key.

Keys = {
    ["FREE-KEY-1"] = true,                    -- works
    ["OLD-KEY-2"]  = false,                   -- disabled
    { Key = "VIP-3333", Active = false },     -- disabled (table style)
}

It works the same in a server list. In a text file add |false after the key, in JSON use true and false as values:

# keys.txt
FREE-KEY-1
OLD-KEY-2|false
VIP-3333|1798761600

{ "FREE-KEY-1": true, "OLD-KEY-2": false }

Check a key without the panel

If your hub has its own key box, you can check the key yourself. Both functions return true or false and follow the same Keys, Url and Validate rules as the panel.

-- only checks, saves nothing
if Library:IsKey("RXM-1234") then
    print("valid")
else
    print("invalid")
end

-- checks and accepts the key (it is saved like in the panel)
local ok, message = Library:SubmitKey(myTextBox.Text)
if not ok then
    warn(message)           -- for example "Invalid key"
end

When the key system is off, IsKey and SubmitKey always return true.

Key list on a website (GrabKeyFromSite)

Keys written inside the script cannot be changed later. With GrabKeyFromSite = true you keep the list in a file you control, so you can add, remove or expire keys without updating the script. The first item of Key is the link.

KeySystem = true,
KeySettings = {
    Title = "My Hub",
    Key = { "https://raw.githubusercontent.com/you/keys/main/keys.txt" },
    GrabKeyFromSite = true,      -- true = the first item of Key is a link
    KeyLink = "https://example.com/get-key",
},

The RXM way to write the same thing is Url = "https://..." inside KeySettings. You can also mix: a Url list and a few keys written in Key work together.

The file can be plain text, one key per line. Lines starting with # are ignored, and | adds an expiry time:

# keys.txt
FREE-KEY-1
VIP-2222|1798761600

Or JSON, either a list or an object with a keys list:

{
  "keys": [
    "FREE-KEY-1",
    { "Key": "VIP-2222", "Expire": 1798761600, "Tier": "VIP" }
  ]
}

The link must return the raw text (for GitHub use the Raw link). Your executor needs request or game:HttpGet. If the server cannot be reached, the panel shows Could not reach the key server, and that try is not counted as a wrong key.

Your own check (Validate)

If you use a key service or your own API, pass a Validate function. It may wait for a web request. Return true for a good key, or false plus a message to show the player. A third value (a table) is stored as the key info.

KeySystem = true,
KeySettings = {
    KeyLink  = "https://example.com/get-key",
    Validate = function(key)
        local url = "https://your-api.example.com/check?key=" .. game:GetService("HttpService"):UrlEncode(key)
        local ok, body = pcall(function() return game:HttpGet(url) end)
        if not ok then
            return false, "Server is offline, try again later"
        end
        if body == "valid" then
            return true, nil, { Tier = "VIP" }       -- ok, message, info
        end
        return false, "That key was rejected"
    end,
}

Saved key and auto login

  • With SaveKey = true, a valid key is written to RXM_Key.txt (change it with FileName, .txt is added if you write no extension). The next time, the saved key is checked silently and the panel is skipped.
  • If the saved key is no longer valid (expired, removed from the list), the file is deleted and the panel opens with a short message.
  • Saving needs writefile, readfile and isfile. Without them the player just types the key each time. Use SaveKey = false to never save.
  • The key is never written into the config file made by SaveConfig.
  • To forget the key from code, call Library:ClearSavedKey(). Players can also press Remove Saved Key in the Settings tab.

Wrong keys and lockout

Each wrong key shakes the panel and shows how many tries are left. After MaxAttempts wrong keys the box locks for Lockout seconds with a countdown, then the tries reset. Use MaxAttempts = 0 for unlimited tries, or KickOnLock = true to kick the player instead of waiting.

Reading the key later

if Library:IsKeyValid() then
    print(Library:GetKey())              -- the accepted key
    print(Library:GetKeyStatusText())    -- "Lifetime" or "2d 4h left"

    local info = Library:GetKeyInfo()    -- { Key, Expire, Tier, Note }
    if info.Tier == "VIP" then
        -- unlock VIP features here
    end
end

Library:GetKeyStatusText() string Lifetime, 2d 4h left or No key.
Library:GetMaskedKey() string Key with the middle hidden, like RXM*********ABC.
Library:GetSavedKey(file) string or nil Reads the saved key from the file.
Library:ClearSavedKey(file) none Deletes the saved key file.
Library:ForgetKey() none Deletes the saved key and marks the session as not logged in.
Library:GetHWID() string Device id used for HWID locks.

Changing the text

The panel follows your UI color, preset, font and transparency, so set them before CreateWindow (or use AutoLoad). Every text can be replaced with Texts, for example to translate it:

KeySystem = true,
KeySettings = {
    Key   = { "RXM-1234-ABCD" },
    Title = "MY HUB",
    Texts = {
        Subtitle = "Masukkan key untuk lanjut",
        Verify   = "Masuk",
        Invalid  = "Key salah",
        Attempts = "Sisa percobaan: %d",     -- %d = tries left
        Locked   = "Coba lagi dalam %ds",     -- %d = seconds left
    },
}

Available text names: Title, Subtitle, Placeholder, Verify, Checking, Accepted, GetKey, Discord, Copied, Empty, Invalid, Expired, WrongDevice, Revoked, Offline, Valid, Attempts, Locked, LockedBtn, LinkCopied, NoClipboard, SavedExpired, Kick.

Keep in mind

A key check inside a Roblox script is only a gate, not a lock. Anyone who can read your script can read the keys written in it, and a determined user can remove the check. Using Url or Validate with your own server is much safer than a fixed list, and the best protection is to keep your real features on the server side of that check.

#8. Colors and theme

Library:SetPreset("Crimson")                       -- ready-made accent color
Library:SetAccent(Color3.fromRGB(255, 60, 80))     -- any color
Library:SetTheme({ Background = Color3.fromRGB(8, 8, 20), Card = Color3.fromRGB(20, 20, 36) })
  • Presets: Monochrome (default), Crimson, Ocean, Violet, Emerald, Sunset, Sakura, Gold.
  • Theme keys: Accent, Accent2, Background, Card, CardHover, Stroke, Track, Off, Text, Muted, Input, Button, Dark.
  • Colors update live: the whole UI changes the moment you call these functions.

Transparency (glass look)

Library:SetTransparency(0.3)          -- 0 = solid, 0.9 = very see-through (default 0.2)
Library:CreateWindow({ Name = "My Hub", Transparency = 0.3 })

The window background, the tab bar, the cards and the notifications become translucent, so the game shows through. Roblox cannot blur the area behind a single UI element, so this is transparency without blur.

Dynamic Island length

Library:CreateWindow({ Name = "My Hub", IslandWidth = 200 })   -- longer pill before opening
Window:SetIslandWidth(160)                                        -- change it any time

Yin-Yang theme

The library can draw a yin-yang by itself (no image asset needed). It is built from UI shapes, so it stays sharp at any size.

-- 1) Loading screen
Library:AddIntro("Balance", { Style = "YinYang", Text = "MY HUB", Subtitle = "BALANCE", Duration = 5 })
Library:SetIntro("Balance")

-- 2) Window icon (the pill and the header icon spin automatically)
local Window = Library:CreateWindow({ Name = "My Hub", Icon = "yinyang" })

-- 3) Draw it anywhere you like
local yy = Library:CreateYinYang(parentFrame, 96)                      -- default: black and white
yy:SetColors(Color3.fromRGB(10, 10, 10), Color3.fromRGB(255, 80, 80))  -- dark half, light half
yy:SetTransparency(0.5)
yy.Frame.Rotation = 45

Every window also shows a faint slow-spinning yin-yang watermark in the panel corner. Turn it off with Effects = { YinYang = false }, Window:SetEffect("YinYang", false), or the Settings tab.

#9. Icons

The library ships with 120+ vector icons, including a yinyang icon. They are drawn in code, so they need no asset ids, they scale cleanly and they take the accent color.

Writing icons manually

local icon = Library.icon

Window:AddTab(icon.sword("Combat"))              -- tab with an icon
Main:Section(icon.combat("Combat"))              -- section with an icon
Main:Section(icon:visual("Visual"))              -- a colon works as well
Main:Toggle(icon.zap({ Name = "Speed", Callback = print }))

There are also plain forms: Window:AddTab("Combat", "sword"), Main:Section("Combat", "sword"), and the Icon = "sword" option on any element.

Where icons can be used

  • Tabs, sections, labels and every element (Icon = "name").
  • The window (CreateWindow({ Icon = "shield" }) or Window:SetIcon("shield")).
  • Notifications (Icon = "bell") and the intro (Icon = "crown").

Finding icon names

print(table.concat(Library:GetIconNames(), ", "))   -- all names

Or add an IconPicker, or use the Settings tab, to browse them with a search box. A few examples: home, settings, search, bell, star, heart, sword, shield, skull, crown, gem, zap, flame, eye, user, users, lock, key, map-pin, globe, gauge, bug, code, terminal, sliders, wifi, play, pause, arrow-up, chevron-down, check, x.

Category aliases

You can write a category name and the library picks a matching icon: combat is sword, main is home, visual and esp are eye, player is user, teleport is map-pin, farm is leaf, misc is box, config is sliders, fps and antilag are gauge, and many more. Add your own:

Library:AddIconAlias("boss", "skull")

Using your own images as icons

Library:AddIcon("logo", "rbxassetid://1234567890")                          -- a single image
Library:AddIcon("sheet1", { Image = "rbxassetid://111", Offset = Vector2.new(0, 0), Size = Vector2.new(48, 48) })  -- sprite sheet
Main:Toggle({ Name = "Custom", Icon = "logo" })

You can also pass an asset id directly: Icon = "rbxassetid://1234567890".

#10. Fonts

The default font is Silkscreen (Creator Store asset 12187371840). The library includes 85 fonts from the Roblox Creator Store and 37 Roblox built-in fonts (122 in total), including Poppins, Inter, Montserrat, Open Sans, Roboto Slab, Pacifico and many more.

Library:SetFont("Poppins")                 -- by name
Library:SetFont(12187371840)               -- by asset id
Library:SetFont("Gotham")                  -- classic Roblox look
Library:AddFont("My Font", 1234567890)     -- register your own font family id
print(table.concat(Library:GetFontNames(), ", "))

local Window = Library:CreateWindow({ Name = "My Hub", Font = "Inter" })
  • Changing the font updates all existing text instantly, including the intro.
  • Some fonts (for example the Noto Serif and M PLUS families for Asian languages) are large, so they can load slowly on phones.
  • Pixel and display fonts are best for short text. Pick a plain font (Inter, Poppins, Open Sans) for long text.

#11. The built-in Settings tab

Window:CreateSettingsTab() adds a ready-made tab where players can customise your hub. By default it only shows Effects. Every other part below is hidden until you set it to false (see "Choose what Settings shows").

  • Appearance: UI color picker, presets, UI scale, UI transparency, Dynamic Island width, hide/show key.
  • Font and Icons: searchable pickers for the UI font, window icon and intro icon.
  • Effects: switch the neon border, glow, aurora, embers, the click, notify, slider and switch sounds and more.
  • Intro: loading-screen switch, intro text, subtitle, image, sound, duration, color, style and a Preview Intro button.
  • Config: Save Config and Load Config buttons.
  • Key (only after a key was used): the masked key, the time left and a Remove Saved Key button.
  • UI: a Destroy UI button that removes the whole UI (tap twice to confirm).

Choose what Settings shows

Pass a table as the second argument. true hides a part, false shows it. Anything you leave out keeps its default.

-- Default: only Effects
Window:CreateSettingsTab("Settings")

-- Also show the Destroy UI button
Window:CreateSettingsTab("Settings", { DestroyUI = false })

-- Also show the color picker, transparency slider and config buttons
Window:CreateSettingsTab("Settings", {
    UIColor = false,
    UITransparency = false,
    Config = false,
})

-- Hide everything (the tab stays, but it is empty)
Window:CreateSettingsTab("Settings", { Effects = true, DestroyUI = true })

Touch and scrolling

On phones, sliders only start moving when you drag sideways. Scrolling up or down over a slider scrolls the page, and a short tap on the track still sets the value.

Saving settings

Library:SaveConfig("MyHub.json")        -- writes color, font, intro and window settings
Library:LoadConfig("MyHub.json")

Saving needs an executor that supports writefile, readfile and isfile. Without them, everything else still works.

#12. Where does my script logic go?

The library only draws the interface. Put your features in callbacks, and keep their state in normal Lua variables:

local RunService = game:GetService("RunService")
local farming, speed = false, 25

Main:Toggle({
    Name = "Auto Farm",
    Callback = function(on)
        farming = on
        if on then
            task.spawn(function()
                while farming do
                    -- your farming logic here
                    task.wait(0.1)
                end
            end)
        end
    end,
})

Main:Slider({ Name = "Speed", Min = 0, Max = 100, Default = speed, Callback = function(v) speed = v end })

local conn
Main:Toggle({
    Name = "Anti Lag",
    Callback = function(on)
        if on then
            conn = RunService.Heartbeat:Connect(function()
                -- your code here
            end)
        elseif conn then
            conn:Disconnect()
            conn = nil
        end
    end,
})

Tips:

  • Toggle is for a feature that stays on or off. Button is for a one-time action.
  • Slider, Dropdown and Input send their value to the callback: store it in a variable and read it in your engine.
  • Long engines can live in their own raw file: call loadstring(game:HttpGet("ENGINE_LINK"))() from a callback.

#14. Troubleshooting

  • Nothing appears: check that the raw link opens in a browser and returns plain Lua text. Run the script again; loading it twice automatically replaces the old UI.
  • Intro image does not show: the id may be a decal or a private asset. Try a different id, an rbxthumb:// link, or a PNG link starting with https:// (needs writefile and getcustomasset). A letter is shown until the image loads.
  • No sound: the sound id must be a public audio asset. The UI sounds can also be switched off in Settings, Effects (Click, Notify, Slider and Switch Sounds).
  • Text looks different: you changed the font. Use Library:SetFont("Gotham") to return to the classic look.
  • A callback fails: the library shows the error message as a red notification. Fix the code inside the callback.
  • Phone layout: the panel resizes automatically. If it is still too big, lower Scale (for example 0.8).
  • Remove the UI completely: show the Destroy UI button with DestroyUI = false in Settings and press it, or call Library:Unload() from your script.
  • My script stops after the key panel: the player closed it, so CreateWindow returned nil. Add if not Window then return end right after CreateWindow.
  • A correct key is rejected: spaces around the key are removed automatically, but upper and lower case matter (set CaseSensitive = false if you want). Also check that Expire is a Unix time in seconds and that HWID matches the player's device.
  • "Could not reach the key server": your executor needs request or game:HttpGet, and the Url must open in a browser and return plain text or JSON. This does not count as a wrong key.
  • The key panel does not show up: KeySettings is only read when KeySystem = true. Also check that you did not call Library:SetKeyEnabled(false) earlier.
  • The key is not remembered: saving needs writefile, readfile and isfile. If the saved key expired, the file is deleted on purpose.
  • The panel is locked: wait for the countdown, or set MaxAttempts = 0 for unlimited tries.
  • The panel closes when I tap outside it: this is by design. Tap the pill again to reopen it.
